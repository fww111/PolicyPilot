# 实验计划与权威性保障（后置执行，2026-10-24 定稿）

> 原则：所有实验固定 seed、公开脚本、控制变量（同语料/同模型 API/同指标）；人工标注双标报告一致性。

## 一、数据集与权威性调研结论（已查证 2026-10-24）

### 政务政策领域：无公认 benchmark（我们的机会）

- 存在零散资源：[SciDB 政务公开信息数据集](https://www.scidb.cn/en/detail?dataSetId=6d3b9baba5d849e1a0d3d3cbf46d641f)（文档+QA对）、政务 KG 数据集（自动抽取）
- 惠企政策匹配/政策时效推理方向：**空白**（专利 CN115470871B 提及政策 NER 数据集但闭源）
- **论文话术**：政务惠企政策领域缺乏公认基准，PolicyBench 填补空白；构建协议（生成器 seed=42 + 人工校对流程）完全公开可复现

### 相邻领域公认基准（作为协议参照与 sanity check）

| 基准 | 领域 | 对我们的作用 |
|---|---|---|
| [KgCLUE](https://github.com/CLUEbenchmark/KgCLUE) | 中文 KBQA | 评测协议参照（指标定义） |
| OpenBG（天池） | 商业知识图谱 | 多子任务组织方式参照 |
| DuIE 2.0 / DuEE | 关系/事件抽取 | 抽取质量指标的公认口径 |
| CAIL | 司法 | 法律文本处理方法论参照 |
| GraphRAG-Bench | 图 RAG | SOTA 对比的评测协议直接参照 |

### PolicyBench 权威性四要素

1. **双标一致性**：两人独立标注 ≥100 题，报告 Cohen's Kappa（≥0.7 可接受）
2. **可复现**：生成器 seed 固定 + 人工校对清单公开 + 数据随代码开源
3. **分层设计**：4 题型 × 3 难度 × 200 题，题型对应创新点（每类都在考现有系统做不到的能力）
4. **SOTA 复现**：所有对比系统跑在同一语料/同一 LLM API/同一机器

## 二、实验矩阵（后置，按优先级）

### E1 资格判定对比（数据已有一半）
- 被试：LLM 直答 / LLM+CoT / 我们的谓词执行
- 题集：扩到 100 题（V1 20 + V2 10 已有，补 70，含 OR 逻辑与嵌套条件）
- 指标：准确率 / 时延 / token / 可解释性评分
- 状态：V1/V2 已完成，剩扩题

### E2 四系统+SOTA 端到端对比（核心实验）
- 被试：朴素RAG / **LightRAG**（港大，已装 1.5.7）/ **HippoRAG 2**（俄州立 ICML25）/ **GraphRAG**（微软，10份子集）/ 朴素图谱 / 朴素双驱动 / **Ours**
- 语料：苏州40+江苏100 全文（同一份）
- 题集：PolicyBench 200 题
- 指标：政策级F1 / 事项级F1 / 溯源命中率 / 拒答校准ECE / 时延 / token
- 状态：LightRAG 脚本就绪（scripts/sota_lightrag.py，index/eval 两阶段）

### E3 构建效率对比（C1 贡献）
- 被试：纯人工 / 纯LLM无约束 / 置信度引导半自动（Ours）
- 数据：B1-B3 批次记录 + 3 份文件的全人工计时基线
- 状态：数据边跑边记（docs/03），差人工基线计时

### E4 本体演化实验（C3 贡献 + 创新 D）
- 数据：B3 的 100 份分 5 批入库
- 指标：每批新增 schema 元素数收敛曲线 / 政策废止后匹配结果失效延迟
- 状态：数据就绪，脚本待写

### E5 迁移实验（附加分 + 创新 E）
- 苏州（首发）vs 常州（迁移）：配置改动行数 / 爬取耗时 / 抽取通过率 / 图谱规模
- 状态：待接入常州源

### E6 消融实验（论文必备）
- Ours-full vs 去仲裁 vs 去谓词 vs 去置信度分流
- 状态：runner 框架支持，等 E2 跑通后配置化

## 三、执行顺序（B3 完成后启动）

```
1. E2 全量（先朴素RAG+LightRAG，再 HippoRAG2，GraphRAG 子集）
2. E1 扩题（70 题新增 + CoT 基线）
3. E4 本体演化（脚本简单，半天）
4. E6 消融
5. E5 迁移（常州源）
6. E3 人工基线（需要队友计时配合）
```
