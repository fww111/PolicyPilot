# 调研与创新点定位（2026-10-22）

> 初赛文档"整体方案设计/相关工作"章节的雏形。每条创新点都必须能回答："别人做到哪，我在哪补位"。

## 一、现状结论

### 政策匹配场景已卷（警示）
- 实在智能"政策计算器"：上传政策→解析→建图谱→推理匹配（2023 起商用）
- 浙大中控"AI政策精准匹配"方案；发明专利 CN112967021A 在先
- 政府落地：广州人社"政策找人"、深圳龙华"政策AI计算器"、宁夏政策计算器
- **结论：仅"LLM 抽要素建图谱做匹配"不构成创新，评委会毙**

### GraphRAG 学术红海但全是通用框架
- 微软 GraphRAG（社区摘要，索引贵）、港大 LightRAG（双层轻量）、俄州立 HippoRAG 2（PPR 多跳最强）
- 无人做政策领域特化（时效/冲突/层级语义）

### LLM 本体构建：活跃但早期
- 2025 综述（arXiv 2510.20345）；主流范式"本体引导抽取"（KaLLM 2024）
- 公认挑战：schema 幻觉、层次归纳不准、缺评测基准 → 机会

### 政策东风
- 2025-10 网信办《政务领域人工智能大模型部署应用指引》
- 行业从"智能问答"向"决策助手 + Agent 自主执行"演进（正好是本题方向，可引用背书）

## 二、现有方案四大空白（论文+落地案例共同承认）

1. 匹配靠要素标签比对，**无跨文档多跳推理**
2. 推荐结果黑盒，**需人工复核**，给不出溯源链
3. 政策更新靠**人工重抽重建**，无本体动态演化
4. 全是封闭商业系统，**无公开评测基准**

# 六、前沿机制借鉴与创新升级（2026-10-23 第二轮调研落地）

## 借鉴一：HippoRAG 2 的 Personalized PageRank → 领域化 PPR 匹配

**机制摘要**（arXiv:2502.14802，ICML 2025）：双节点图（passage+phrase），Query 匹配 phrase 节点作种子，PPR 从种子扩散，多路径可达节点累积更高分数；用 LLM triple filtering 去噪（比 v1 提升约 7%）。

**我们的落地**（`graph/memory_engine.py::match_policies_for`）：
- 种子 = 企业画像类别节点（行业/规模/资质/区域），概率质量均匀分布在种子上（personalization 向量）
- 沿 APPLIES_TO/CONFLICTS_WITH/HAS_SUBSIDY 等边扩散，**多跳关联的 Subsidy 天然得分更高**——替代朴素一跳标签匹配
- 我们的置信度分流（<0.75 人工复核）在功能上对标其 triple filtering，且更进一步：闭环回填 few-shot

**差异化声明**：HippoRAG 2 是通用记忆框架；我们是政策领域特化（种子是结构化企业画像而非查询文本，边带政策语义），并集成失效传播（见下）。

## 借鉴二：Graphiti 双时间轴 → 级联失效传播（创新点③技术内核）

**机制摘要**（arXiv:2501.13956）：每条边四个时间戳（valid_at/invalid_at 现实时间 + created_at/expired_at 系统时间）；新事实与旧事实冲突时旧边打 invalid_at 失效**而非删除**（保留审计轨迹，支持 point-in-time 查询），冲突消解时新信息优先。

**我们的落地**（`memory_engine.py::invalidate_policy_edges`）：
- 政策废止（SUPERSEDES 建立）→ 自动级联：政策的 HAS_SUBSIDY 边失效 → 其 Subsidy 的 APPLIES_TO/REQUIRES 等出边一并失效
- 查询侧通过"有效边视图 + 种子可达闭包"自动排除失效子图——**企业匹配结果随政策废止即时消失，无需重算全图**
- 影响面报告（失效边数/受影响事项清单）输出给溯源链：可回答"我的旧结论为什么变了"

**差异化声明**：Graphiti 面向对话记忆的边级失效；我们做政策领域的事件级级联（一次废止事件 → 整棵事项子树失效），这是商业产品"人工重抽重建"做不到的自动化能力。

## 借鉴三（计划中）：LightRAG 双层检索 → 检索 Agent 切片策略

low-level（实体级）/high-level（关系主题级）双层检索思想，W3 知识库建设时落地为：实体卡片层（Subsidy/条件结构化卡）+ 政策原文层（章节切片），检索 Agent 先实体后原文。

## 工程副产品：零依赖轻量图引擎

memory 引擎（networkx）与 Neo4j 双形态同接口（GRAPH_ENGINE 切换）。轻量形态 = **"Skill 模板轻量化迁移"附加分**的技术载体：迁到新城市/新行业时 pip install networkx 即可跑全套推理，无需部署图数据库。

# 七、独有创新与对比实验设计（2026-10-23 定稿，科研级）

借鉴组装之上，提出两个自有机制（代码已落地并单测通过）：

## 独有创新①：双通道互验仲裁（agent/cross_validation.py）

把赛题"检索-推理双驱动"从**串联架构**升级为**互验机制**：
- 图谱结论必须有 RAG 原文支撑、RAG 结论必须有图谱路径背书
- 四级裁决：ACCEPTED(双证一致) / DEGRADED(单证) / RETRY(冲突重查) / REJECTED(仍冲突则拒答+分歧说明)
- **拒答是特性**：政务场景答错比不答严重，且拒答附带两通道各自依据（可溯源的"不知道"）

**对比实验矩阵**（四系统两消融，评测集四类题型）：
| 系统 | 机制 | 指标 |
|---|---|---|
| B1 纯RAG | 向量检索+LLM | 准确率/溯源命中率 |
| B2 纯图谱 | 标签匹配 | 同上 |
| B3 朴素双驱动 | 串联拼接 | 同上 |
| **Ours** | **互验+仲裁** | 同上 + **风险校准度**（答错时的自信度分布）|
| 消融1 | 去仲裁 | 证明互验贡献 |
| 消融2 | 去谓词执行 | 证明符号层贡献 |

## 独有创新②：可执行条件谓词（eval/predicate_exec.py，neuro-symbolic）

现有产品条件判断=标签匹配+LLM现场判断，组合逻辑易错且不可解释。
我们：LLM 抽取 Condition(field/op/value) -> 符号精确执行：
- 零LLM调用、毫秒级、逐条件可解释输出
- 三值语义：满足/不满足/**待补信息**（字段缺失≠不符合——政务上是"带材料补"而非"你不行"）

**对比实验**：同一批资格判断题（构造含 AND/OR/数值边界 的难例），端到端LLM判断 vs 谓词执行，测准确率/时延/成本/可解释性。预期LLM在数值边界与组合逻辑上显著翻车。
