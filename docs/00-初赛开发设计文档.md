## 一、项目概述

### 1.1 背景与痛点

惠企政策是政府扶持实体经济的关键工具，但政策落地存在"最后一公里"梗阻：**政策找不到、读不懂、不会申、材料反复交**。从技术视角调研（商业方案、学术论文、政府落地案例三方交叉验证），现有"政策匹配"产品普遍存在四个空白：

1. **匹配靠要素标签比对，无跨文档多跳推理**——"该政策是否已被新文件废止"需跨两份文件才能回答，标签体系无能为力；
2. **推荐结果黑盒、需人工复核**（《面向企业的政策智能匹配推送系统研究》，计算机应用 2025）——给不出"为什么推荐、依据哪条、与什么冲突"的溯源链；
3. **政策一更新就得人工重抽重建**——政务知识体系月度级迭代，固定知识库无法适配；
4. **封闭商业系统、无公开评测基准**——实在智能"政策计算器"、浙大中控方案等均闭源，领域缺少可复现的研究基础。

同时，通用 GraphRAG 框架（微软 GraphRAG、港大 LightRAG、俄州立 HippoRAG 2）虽在多跳检索上取得进展，但均缺乏政策领域的**时效、冲突、层级**语义。

### 1.2 方案定位（一句话）

> 现有政策匹配产品停在"要素标签比对 + 人工复核"，通用 GraphRAG 框架缺乏政策的时效/冲突/层级语义；本工作在华为 Nexent 平台上构建**可进化、可溯源**的惠企政策决策智能体——本体半自动构建、双通道互验仲裁、级联失效演化三位一体，并开源首个政务政策匹配评测基准。

### 1.3 政策背书

2025 年 10 月中央网信办《政务领域人工智能大模型部署应用指引》、2025 年 8 月国务院"人工智能+"行动意见，均指向"精准识别需求、主动规划服务"的政务服务智能体方向——本工作正处该演进路径上。

## 二、整体方案设计

### 2.1 三层架构

```
┌─────────────────────────── 智能体层（Nexent 平台）───────────────────────────┐
│  检索 Agent（政策原文 RAG 证据） ⇄ 互验仲裁 ⇄ 推理 Agent（图谱多跳）          │
│  四级裁决：采纳 / 降置信 / 仲裁重查 / 拒答（拒答附两通道分歧依据）             │
│  MCP 工具×5：图谱查询 / 画像抽取 / 时效检查 / 资格谓词判断 / 互验仲裁          │
├─────────────────────────── 知识层（双引擎图谱）─────────────────────────────┤
│  三维政策本体：SUPERSEDES(废止链) / CONFLICTS_WITH(互斥) / BELONGS_TO(层级)   │
│  PPR 匹配（企业画像种子扩散）· 级联失效传播 · 时间感知边（valid_at/invalid_at） │
│  引擎：Neo4j（生产）/ networkx（轻量，模板迁移零依赖）                        │
├─────────────────────────── 数据层（异构统一）───────────────────────────────┤
│  结构化源：gov.cn 政策库接口元数据（249条，直入图谱，零LLM零幻觉）             │
│  非结构化源：江苏省政府全文（100份，dataproxy 全量库5238条可扩）               │
│              苏州市政府全文（40份）                                           │
│  处理管线：解析(静态提取/MinerU预留) → LLM本体约束抽取 → 置信度分流            │
└──────────────────────────────────────────────────────────────────────────────┘
```

### 2.2 设计原则

- **组装创新 + 领域创新，不做底层发明**：MinerU/Neo4j/Nexent/MCP 等成熟组件以独立进程集成（规避许可证传染），创新密度集中在领域本体、互验机制、演化算法；
- **零依赖轻量形态**：networkx 引擎使全套推理 `pip install` 即可运行——支撑"Skill 模板轻量化迁移"（换城市/行业只换数据不换引擎）；
- **拒答是特性**：政务场景答错比不答严重，系统的"不知道"必须可溯源。

## 三、知识图谱构建方案

### 3.1 三维政策本体（领域创新①）

区别于现有产品的"要素标签"，本工作将三类领域关系建模为一等公民：

| 维度 | 关系 | 语义 | 支撑的多跳问题 |
|---|---|---|---|
| 时效 | `SUPERSEDES` | 新政策废止旧政策 | "X 还能申请吗？"（跨 2+ 文件追溯现行版本） |
| 冲突 | `CONFLICTS_WITH` | 同类支持不可重复申领 | "已享受 A 还能申 B 吗？" |
| 层级 | `BELONGS_TO` | 政策隶属/主题分类体系 | "区级政策与市级体系什么关系？" |

实体：Policy（文号唯一键）/ Subsidy（支持事项）/ Enterprise（画像，字段对齐 GB/T 4754 国标行业分类）/ Material / Department / **Condition（可执行谓词：field/op/value）**。

### 3.2 低资源半自动构建闭环（领域创新②）

```
政策全文 → LLM 本体约束抽取（ONTOLOGY_PROMPT 白名单约束输出）
        → 置信度自评 → ≥0.75 自动入库 / <0.75 人工复核队列
        → 人工修正回填 few-shot 示例（越抽越准）
```

量化记录（docs/03，边跑边记）：

| 批次 | 文件数 | 三元组 | 自动通过率 | token 成本 | 备注 |
|---|---|---|---|---|---|
| B1 | 19 | 87 | 53% | 13.5 万 | 校准批次，暴露两类数据形态问题 |
| B2 | 42 | 90 | 53% | 22.4 万 | 证实首页语料质量差 → 转向定向源 |
| B3 | 100 | 进行中 | — | — | 江苏省定向高质量语料 |

### 3.3 时间感知与级联失效（领域创新③，借鉴 Graphiti 双时间轴）

每条边携带 `valid_at/created_at/invalid_at` 时间戳。政策废止（SUPERSEDES 建立）触发**级联失效**：政策的 HAS_SUBSIDY 边失效 → 其全部 Subsidy 的出边一并失效（失效不删除，保留审计轨迹）。查询侧通过"有效边视图 + 种子可达闭包"自动排除失效子图——**企业匹配结果随政策废止即时消失，输出影响面报告（"您的旧结论为何变化"），无需人工重抽重建**。

已验证：模拟废止事件后匹配结果正确归零，影响面报告输出受影响事项清单。

## 四、智能体构建方案

### 4.1 双通道互验仲裁（独有创新④）

赛题要求"检索-推理双驱动"，常见实现是两 Agent 串联——本工作将其升级为**互验机制**：

- 图谱通道结论必须有 RAG 原文支撑、RAG 结论必须有图谱路径背书（含跨通道 ID 规范对齐层）；
- 四级裁决：**采纳**（双证一致）/ **降置信**（单证）/ **仲裁重查**（冲突触发一次）/ **拒答**（仍冲突，附两通道各自依据）。

已在苏州真实政策语料端到端验证：文旅企业画像 → 图谱通道（入境旅游措施 3 事项）× RAG 通道（原文检索 6 事项）→ 交集裁决"采纳"，置信 0.5。

### 4.2 可执行条件谓词（独有创新⑤，neuro-symbolic）

申报条件抽取为结构化谓词后**符号精确执行**（支持 EQ/GT/GTE/LT/LTE/IN/CONTAINS/NOT_CONTAINS），三值语义：满足 / 不满足 / **待补信息**（字段缺失≠不符合——政务上是"带材料补"而非"你不行"）。零 LLM 调用、毫秒级、逐条件可解释。

### 4.3 Nexent 集成

- MCP 服务（SSE 模式，端口 8765）暴露 5 工具：`query_policy_graph`（多跳查询）/ `extract_enterprise_profile` / `check_policy_validity`（时效）/ `check_eligibility`（谓词判断）/ `cross_validate_answers`（互验仲裁）；
- Nexent UI → 智能体开发 → MCP 配置 → `http://host.docker.internal:8765/sse`（Docker 部署细节）；
- Skills 工作流：意图解析 → 画像抽取 → 图谱匹配（PPR）→ 原文回捞 → 条件判定 → 冲突检测 → 互验仲裁 → 带溯源链报告。

## 六、数据处理说明

1. **解析层**：统一中间格式 ParsedDocument（正文+表格+元数据）；政府站正文选择器优先（苏州 .detail-mod 等）+ 链接密度启发式兜底；
2. **抽取层**：见 3.2；输出 Triple（含 evidence 原文摘录——溯源链终点）；
3. **归一层**：类别节点规范化（cond_ 前缀→行业:/资质:/区域:）；
4. **评测集**：程序化生成四类题型（多跳匹配/时效/冲突/溯源），seed=42 可复现，附人工校对清单（docs/06）。

## 七、效果验证（实验数据）

### 实验 1：资格判断——端到端 LLM vs 条件谓词（20+10 题，可复现）

| 条件复杂度 | 端到端 LLM | 条件谓词 | 结论 |
|---|---|---|---|
| 简单（单层 AND，20 题） | 100% / 4.5s/题 / 8890 tok | 100% / <1ms / 0 tok | 打平；谓词优势=千倍时延+零成本 |
| 复杂（长列表/区间链/例外条款，10 题） | **80%** / 8.5s / 7375 tok | **100%** / <1ms / 0 | LLM 失败模式=过度保守（把"满足"误判"待补"） |

（过程含一次科学修正：解析器 bug 曾致 LLM 虚低 70%，修复后取公平值——被试系统工程质量影响实验结论，已记录。）

### 实验 2：四系统对比（框架就绪，B3 数据落定后全量）

纯 RAG / 纯图谱 / 朴素双驱动 / 互验四系统统一评测，双层评分（政策级公平口径+事项级严格口径），指标：F1、溯源命中率、拒答行为、风险校准度。
