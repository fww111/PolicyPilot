# 条款级合规审查场景升级方案（docs/10，2026-10-24）

> 外部战略分析（用户引入）的核心主张：把决策对象从"回答政策问题"收敛到"条款级合规冲突审查"——对错由法律效力层级做客观标尺，复核反馈驱动进化。本文档记录结合本项目已有资产的**取舍结论**与落地设计。

## 一、取舍结论（结合已有资产逐项裁决）

| 外部分析建议 | 本项目现状 | 裁决 |
|---|---|---|
| 场景收窄到条款级冲突审查 | 已有"惠企政策匹配"场景（端到端已通） | **双场景并存**：匹配（面向企业）+ 审查（面向法制部门）。不扔匹配——它是业务价值叙事；新增审查——它有客观对错标尺，是"可进化"的实证载体 |
| check_temporal_validity 时效工具 | **已有** check_policy_validity（SUPERSEDES 链） | 保留，增强返回效力层级 |
| 效力层级编码（法律>法规>规章>规范性文件） | BELONGS_TO 目前是主题分类用法 | **扩展**：Policy 增 authority_level 字段（1-5），新增 SUPERIOR_TO 关系 |
| 条款级实体 | 本体粒度是"政策→事项"，无条款 | **新增 Article 实体**（{policy_id}#A{n}）+ HAS_ARTICLE / 条款级 CONFLICTS_WITH |
| Verifier 确定性核验（生成-核验-打回） | 溯源有 evidence 但无逐字校验 | **立即实现**（性价比之王：实现极简、100%精度可复现、直接命中"可溯源"题眼） |
| Skill 策略版本迭代（v1→反馈→v2 回测） | Nexent 版本管理已验证（2 版） | **建反馈库 + 回测脚本**，演示"误报如何被纠正" |
| 12345 执行端弱信号 | 无 | **文档层设计，不实做**（初赛时间账） |
| 记忆层偏好沉淀 | Nexent 记忆功能已见 | 演示层提及，不深做 |

## 二、审查场景的决策定义（写进材料的版本）

> 输入：一份待审政策文件的条款 + 上位法库（国家法律/行政法规/部门规章 + 本级现行有效文件）
> 输出：逐条款的审查结论 `{conflict: 是/否/存疑, 冲突对象, 效力依据, 原文引用(逐字核验), 修改建议}`
> 对错标尺：效力层级（authority_level）+ 时间效力（现行有效）+ 复核人员结构化反馈
> 人在回路：智能体输出冲突线索与建议，最终判断权在法制审核人员（合规边界）

## 三、技术设计（增量，全部落在已有骨架上）

### 3.1 本体扩展（policy_ontology.py）
- 新实体 `Article`：article_id / text（条款原文）/ article_no
- 新关系：`HAS_ARTICLE`（Policy→Article）、`SUPERIOR_TO`（效力层级，Policy/Article 间）、`CONFLICTS_WITH` 扩展语义注释（条款级方向性：下位冲突上位）
- Policy 增字段：`authority_level: int`（1法律 2行政法规 3部门规章 4地方性法规/政府规章 5规范性文件）
- ONTOLOGY_PROMPT 同步更新（抽取条款与层级）

### 3.2 Verifier 确定性核验器（agent/verifier.py，性价比之王）
- 输入：智能体回答文本 + 源文档语料
- 流程：引用片段抽取（引号/【】/"依据"句式）→ 规范化（全半角/空白）→ 逐字子串匹配 → 未通过即打回
- 输出：`{verified: [...], rejected: [...]}`，rejected 附原因
- 卖点：**确定性、零幻觉、100% 精度可复现**——"看起来像冲突"与"法律上确实构成冲突"的分界线

### 3.3 MCP 工具扩展（mcp_server）
- 新增 `check_authority_level(id_a, id_b)`：效力层级比较（规则可枚举，确定性）
- 新增 `trace_conflict_evidence(id_a, id_b)`：返回两条原文（逐字）
- 新增 `verify_citations(text)`：Verifier 的 MCP 封装（Verifier 节点用）
- `check_policy_validity` 增强：返回 authority_level

### 3.4 反馈闭环（进化实证的燃料）
- `data/feedback/review_log.jsonl`：复核记录 `{case_id, article_id, verdict: confirmed/rejected, reason, reviewer, ts}`
- 回测脚本：v1 判定集 vs 反馈修正后的 v2 判定集，报告误报率变化与召回保持
- Nexent 版本管理天然承载 Skill v1/v2（已验证 2 版）

## 四、效果保障（每项可验证）

| 组件 | 验证方式 |
|---|---|
| Verifier | 构造 10 条含伪造引用的回答 → 100% 拦截；10 条真实引用 → 0 误拦 |
| 效力层级 | 规则单测：法律>法规>规章>规范性文件 全排列 |
| 冲突检测 | 自建标注集：gov.cn 真实"新文件废止旧文件"案例 = 真冲突对（金标准天然存在） |
| 进化叙事 | v1 构造误报 → 结构化反馈 → v2 策略约束 → 历史回测误报率下降（脚本化） |

## 五、叙事定位更新

- 演示双场景：企业端"能申什么"（匹配）+ 法制端"条款是否冲突"（审查）
- 进化的实证不是"模型变大"，而是"**v1 误报 → 复核驳回 → v2 不再误报且召回不降**"的完整链路
- 溯源从"有 evidence"升级为"**逐字核验过的 evidence**"——Verifier 是与所有 GraphRAG 系差异化的一点
