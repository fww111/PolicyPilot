## 一、这是什么

**PolicyPilot 是一个跑在华为 Nexent 平台上的惠企政策决策智能体。**

企业问"我们能申什么政策"，它给出**带政策原文证据的可申清单**；法制人员问"这条条款有没有问题"，它给出**带效力层级依据的冲突审查结论**。

政府每天发布海量惠企政策，但企业找不到、看不懂、不会申；现有产品只能做"标签匹配"，推荐结果是黑盒。PolicyPilot 把沉睡的政策文件变成一张**结构化政策知识图谱**，让智能体在图上做**多跳推理**，且每个结论都**逐字可溯源**到政策原文条款。

### 双场景决策（均已端到端跑通）

| 场景 | 用户 | 决策输出 | 对错标尺 |
|---|---|---|---|
| **政策匹配** | 企业 | 可申事项清单 + 文号 + 证据链 | 复现实验集 |
| **条款合规审查** | 法制部门 | 是否冲突 / 冲突点 / 依据 / 修改建议 | **法律效力层级（客观）** |

## 二、核心功能

### 1. 三维政策知识图谱

政策文件被抽取为图谱，三类领域关系是一等公民：

- **时效维** `SUPERSEDES`——新政策废止旧政策，回答"这政策还能申吗"（跨文档多跳）
- **冲突维** `CONFLICTS_WITH`——同类补贴不可重复申领
- **层级维** `SUPERIOR_TO` / `BELONGS_TO`——效力层级（法律>法规>规章>规范性文件）+ 主题分类

当前规模：**636 节点 / 678 边 / 13 条真实废止链**，语料来自江苏省政府（100 份带文号全文）、苏州市政府（40 份）、中国政府网政策库元数据（249 条），全部公开可复现。

### 2. 神经符号混合的资格判定（Neuro-Symbolic）

申报条件（"成立≤3年 且 营收≥500万"）被抽取为**可执行谓词**，由符号引擎精确执行，而非 LLM 现场判断：

- 零 LLM 调用、毫秒级、逐条件可解释
- 政务特有**三值语义**：满足 / 不满足 / **待补信息**（字段缺失 ≠ 不符合——是"带材料来补"不是"你不行"）

### 3. 双通道互验仲裁（检索-推理双驱动的正确打开方式）

图谱结论必须有 RAG 原文支撑，RAG 结论必须有图谱路径背书；冲突触发仲裁重查，仍冲突则**拒答并附两通道各自依据**。拒答是特性——政务场景"可溯源地不知道"比瞎答值钱。

### 4. Verifier 确定性引用核验

智能体引用的每条原文做**规范化逐字核验**，未逐字出现在源文件中的引用一律打回（生成-核验-打回闭环）：

```
真实引用（含转述尾巴） → ✅ 放行      伪造引用（近似转述） → 🚫 100% 拦截
```

"看起来像冲突"与"法律上确实构成冲突"，从此有分界线。

### 5. 数据资产目录（沉睡资产激活的量化）

全 pipeline 数据物登记为资产台账（153 项）：`raw → parsed → structured → serving` 血缘链，**唤醒率 65.33%**（沉睡文件被激活为可服务图谱知识的占比）。

## 三、创新点与实验证据

| # | 创新点 | 实验证据 |
|---|---|---|
| 1 | **三维政策本体**（时效/冲突/层级），补通用 GraphRAG 系的领域语义空白 | 13 条真实废止链支持跨文档多跳；通用框架均无此能力 |
| 2 | **低资源半自动本体构建闭环**：本体约束抽取→置信度分流→人工只审低置信→修正回填 | 152 份文件 / 16.2 万 tokens / 53% 自动通过率；行业字段对齐 GB/T 4754 |
| 3 | **可执行条件谓词 vs 端到端 LLM**（神经符号） | 简单条件打平（100% vs 100%，诚实记录）；复杂条件（长列表/区间/例外条款）**LLM 80% vs 谓词 100%**，LLM 失败模式=过度保守；谓词时延千倍优、零 token |
| 4 | **可进化**：级联失效（政策废止→匹配即时归零）+ 复核反馈驱动策略迭代 | v1 误报 2 → 法制反馈 → v2 **准确率 60%→80%，召回零损失** |
| 5 | **Verifier 确定性核验** | 伪造引用 100% 拦截、真实引用零误拦（四场景实测） |
| 6 | **模板轻量化迁移**（附加分） | 换数据源仅改 **1 行配置**，解析通过率 100%，1.7 分钟抓取 20 份 |
| 7 | **PolicyBench 评测基准**（4 题型：多跳/时效/冲突/溯源） | 政务惠企政策领域首个开源基准（该领域此前无公认 benchmark） |
| 8 | **本体演化实验**：152 份分 5 批重放 | 批 1 引入 12 个 schema 元素后收敛 → 提出"约束-演化交替"治理机制 |

详细设计依据见 [docs/](docs/)（调研、赛题差距审计、场景升级方案、实验计划）。

## 四、架构

```
┌─────────────────────────── 智能体层（Nexent 平台）───────────────────────────┐
│  检索 Agent（政策原文 RAG 证据） ⇄ 互验仲裁 ⇄ 推理 Agent（图谱多跳）          │
│  四级裁决：采纳 / 降置信 / 仲裁重查 / 拒答（拒答附两通道分歧依据）             │
│  L2 Skill×4：画像 / 匹配+核验 / 条款合规审查 / 画像抽取器                     │
├─────────────────────────── 知识层（双引擎图谱）─────────────────────────────┤
│  三维本体：SUPERSEDES / CONFLICTS_WITH / SUPERIOR_TO + Article 条款实体       │
│  PPR 匹配（画像种子扩散）· 级联失效传播 · 时间感知边（valid_at/invalid_at）    │
│  引擎：networkx（零依赖轻量，模板迁移形态）/ Neo4j（生产）                    │
├─────────────────────────── 数据层（异构统一 + 资产目录）────────────────────┤
│  结构化源：gov.cn 政策库元数据（249 条，直入图谱零幻觉）                       │
│  非结构化源：江苏省政府全文（100 份）/ 苏州市政府（40 份）                     │
│  管线：解析 → LLM 本体约束抽取 → 置信度分流 → 人工复核闭环                     │
└──────────────────────────────────────────────────────────────────────────────┘
        ↕ 8 个自研 MCP 工具（图谱查询/画像抽取/时效检查/资格谓词/互验仲裁/效力层级/冲突溯源/引用核验）
```

## 五、快速开始

```bash
# 1. 安装依赖（uv 自动建 .venv）
uv sync

# 2. 配置环境变量（大模型 API + 图引擎）
cp .env.example .env   # 填入 LLM_API_KEY（OpenAI 兼容接口均可）

# 3. 环境健康检查
uv run python scripts/setup_check.py

# 4. 冒烟测试（不依赖外部服务）
uv run pytest -v

# 5. 采集政策语料（江苏省政府政策库，约 20 分钟/30 份）
uv run python scripts/crawl_jiangsu.py 30

# 6. 本体约束抽取（LLM）+ 建图
uv run python scripts/b1_extract.py
uv run python scripts/build_graph.py

# 7. 启动 MCP 服务（供 Nexent 接入）
MCP_TRANSPORT=sse uv run python -m policy_pilot.mcp_server.server

# 8. 数据资产台账（唤醒漏斗）
uv run python -m policy_pilot.feedback.asset_registry
```

### 接入 Nexent 平台

1. 本地部署 [Nexent](https://github.com/ModelEngine-Group/nexent)：`bash deploy.sh --defaults docker --image-source mainland`
2. 启动本仓库 MCP 服务（SSE 模式，端口 8765）
3. Nexent UI → 资源管理 → 租户 → **MCP 配置** → 添加 `http://host.docker.internal:8765/sse`
4. 智能体开发 → 选择 8 个 policy_pilot 工具 + 4 个 Skill → 发布
